| [Home Assistant Core](https://github.com/home-assistant/core)'s published image at the digest `pin.nix` selects (release `2026.10.3`) | [Apache-2.0](https://github.com/home-assistant/core/blob/2026.10.3/LICENSE.md), the label upstream puts on the image (`org.opencontainers.image.licenses`) and the file that travels inside it, discharging §4(a); Core publishes no `NOTICE` at that tag, so §4(d) sends nothing from it. The copy is digest-preserving and adds, edits, and removes no byte, so everything else in the assembly keeps its own terms and upstream's own record inside the image names them — per-distribution `*.dist-info/METADATA` for the Python environment, Alpine's per-package index records for the userland                                                                                                                                                                                                                                                                                                                                                                  |
| What in that record changes what a conveyer owes                                                                                      | GPL- and LGPL-family packages that conveying a copy triggers; four AGPL-family distributions, whose §13 reaches users interacting with a served web UI and whose corresponding source is upstream's to provide; `ld2410-ble==0.1.1` declared only `Other/Proprietary License`, fifteen names declaring nothing and one (`maxcube-api==0.4.3`) only a setuptools placeholder — unverified here, not assumed permissive; `home-assistant-intents==2026.10.6`, whose wheel declares Apache-2.0 while its [repository](https://github.com/home-assistant/intents/blob/main/LICENSE.md) carries [CC-BY-4.0](https://spdx.org/licenses/CC-BY-4.0.html), so treat attribution as possibly attached; PicoTTS's `NOTICE` files, which §4(d) requires of whoever builds and conveys that binary rather than of this flake; upstream's own patches, travelling under the licence of the code they modify (its CPython patches under PSF, its telldus-core patches under LGPL-2.1) |

Everything above is read from upstream's published manifest, configuration blob, and build recipes at the pinned versions rather than from unpacked layers, so a build conveys nothing and the terms attach to whoever moves the built store path beyond their own trust boundary — which this repository's CI push to its own access-controlled cache is not.
